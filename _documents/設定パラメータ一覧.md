# 設定パラメータ一覧

設定は **Pleasanter 本体と同じ方式**で `App_Data/Parameters/*.json` と環境変数から読む。

- **優先順位は `{名前}.local.json` ＞ 環境変数 ＞ `{名前}.json`**（[`App_Data/Parameters/README.md`](../App_Data/Parameters/README.md)）
- **資格情報の実値（DB の接続文字列・`IDP_SECRET_KEY`）は JSON へ書かない。** 環境変数か Key Vault から与える
- **書き間違いは起動時に止める。** 黙って既定へ落とすと、締め出しを 5 回にしたつもりで効いていない、といったことが起きる

JSON のキーと環境変数の名前が違うものは、下の表の「JSON のキー」で示す（環境変数が優先）。

## 必須

| 環境変数 | 内容 |
| --- | --- |
| `IDP_SECRET_KEY` | 署名鍵の秘密鍵を暗号化する鍵（Base64 の 32 バイト）と、cookie の署名鍵の元。**失うと保存済みの署名鍵が復号できなくなる。** 控えを取ること。`dotnet …Web.dll --generate-secret-key` で作れる |
| `IDP_DB_PROVIDER` | IdP 自身の DB の種類。`SqlServer`（既定）/ `PostgreSql` / `MySql` / `Sqlite` |
| `IDP_DB_CONNECTIONSTRING` | IdP 自身の DB の接続文字列。SQLite だけは省略でき、`App_Data/idp.db` を作る |
| `IDP_PLEASANTER_DB_PROVIDER` | Pleasanter の DB の種類。`SqlServer`（既定）/ `PostgreSql` / `MySql` |
| `IDP_PLEASANTER_DB_CONNECTIONSTRING` | Pleasanter の DB の接続文字列。**読み取り専用のユーザーを使う** |
| `IDP_ISSUER` | IdP の外から見える URL（末尾の `/` なし。サブパスへ置くときはサブパス込み）。OIDC の `iss` と SAML の EntityID になる。未設定は `http://localhost:8081`。`https` が必要（`localhost` / ループバックと `IDP_ALLOW_INSECURE=true` の場合を除く） |

## 認証と TOTP（`Security.json`）

| JSON のキー | 環境変数 | 既定 | 内容 |
| --- | --- | --- | --- |
| `LoginMaxFailures` | `IDP_LOGIN_MAX_FAILURES` | 5 | 失敗できる回数（パスワードと TOTP を合わせて数える）。1〜100 |
| `LoginFailureWindowMinutes` | `IDP_LOGIN_FAILURE_WINDOW_MINUTES` | 15 | 失敗を数える期間（分）。1〜1440 |
| `LoginLockoutMinutes` | `IDP_LOGIN_LOCKOUT_MINUTES` | 15 | 締め出す時間（分）。1〜1440 |
| `TotpMode` | `IDP_TOTP_MODE` | `Auto` | `Auto`（登録済みの人に求める）/ `Pleasanter`（Pleasanter の設定に従う） |
| `SecondaryAuthentication.Mode` | `SecondaryAuthentication__Mode` | `None` | `TotpMode=Pleasanter` のとき。`None` / `DefaultEnable` / `DefaultDisable`（Pleasanter の `Security.json` と同じ意味） |
| `SecondaryAuthentication.CountTolerances` | `SecondaryAuthentication__CountTolerances` | 1 | TOTP で許す前の時間枠の数（1 枠 = 30 秒）。0〜3。加えて後ろ 1 枠を許す |

## 動作（`Service.json`）

| JSON のキー | 環境変数 | 既定 | 内容 |
| --- | --- | --- | --- |
| `Issuer` | `IDP_ISSUER` | — | 上記 |
| `SessionLifetimeMinutes` | `IDP_SESSION_LIFETIME_MINUTES` | 480 | SSO セッションの絶対的な有効時間（分）。5〜43200 |
| `SessionIdleMinutes` | `IDP_SESSION_IDLE_MINUTES` | 120 | 無操作の許容時間（分）。1〜43200 |
| `AuthorizationCodeLifetimeSeconds` | `IDP_AUTHORIZATION_CODE_LIFETIME_SECONDS` | 60 | 認可コードの有効時間（秒）。10〜600 |
| `AccessTokenLifetimeSeconds` | `IDP_ACCESS_TOKEN_LIFETIME_SECONDS` | 600 | アクセストークン（クライアントごとに上書き可）。60〜86400 |
| `IdTokenLifetimeSeconds` | `IDP_ID_TOKEN_LIFETIME_SECONDS` | 600 | ID トークン。60〜86400 |
| `RefreshTokenLifetimeSeconds` | `IDP_REFRESH_TOKEN_LIFETIME_SECONDS` | 2592000 | リフレッシュトークン（クライアントごとに上書き可）。300〜31536000 |
| `SamlAssertionLifetimeSeconds` | `IDP_SAML_ASSERTION_LIFETIME_SECONDS` | 300 | SAML アサーション。30〜3600 |
| `AdminRole` | `IDP_ADMIN_ROLE` | `ServiceManager` | 管理画面へ入れる役割。`ServiceManager` / `TenantManager`（テナント管理者以上） |
| `AdminLoginIds` | `IDP_ADMIN_LOGIN_IDS` | 空 | 管理者をログイン ID で絞る（カンマ区切り）。**絞るだけで、役割を満たさない人は管理者にならない** |

⚠️ **Pleasanter の既定の管理者 `Administrator` は `TenantManager` だけを持つ**（`ServiceManager` ではない。実機で確認）。
そのまま管理画面へ入れるなら `IDP_ADMIN_ROLE=TenantManager` にする。本番では、管理者を `ServiceManager` に限る
（既定のまま）か、`IDP_ADMIN_LOGIN_IDS` で絞るのがよい。

## レート制限・保持期間

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `IDP_RATE_LIMIT_LOGIN_PER_MINUTE` | 20 | ログインの POST（パスワード・TOTP）の、IP ごとの 1 分あたりの上限 |
| `IDP_RATE_LIMIT_TOKEN_PER_MINUTE` | 120 | トークン・失効エンドポイントの、IP ごとの 1 分あたりの上限 |
| `IDP_AUDIT_RETENTION_DAYS` | 365 | 監査ログを残す日数。0 なら消さない |

**同じ出口（NAT・プロキシ）から多数の利用者が入る構成では、IP ごとの上限を緩める。**
ログイン失敗の締め出しは DB 側（ログイン ID ごと）で、これとは別。

## 配置・ネットワーク

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `IDP_PATH_BASE` | なし | サブパス（例 `/idp`）へ置くとき。先頭 `/`・末尾 `/` なし。設定すると、その外の経路は 404（`/healthz` `/ready` を除く） |
| `IDP_ADMIN_PATH` | `/admin` | 管理画面の入口。小文字・数字・ハイフンのみ |
| `IDP_FORWARDED_NETWORKS` | なし | 転送ヘッダ（`X-Forwarded-For` / `-Proto`）を信じるプロキシの CIDR（カンマ区切り）。**指定しないと信じない** |
| `IDP_HEALTH_NETWORKS` | なし | `/healthz` `/ready` を見せる送信元の CIDR。範囲外には 404 |
| `IDP_ALLOW_INSECURE` | `false` | HTTP（平文）を許す。HTTPS へのリダイレクトと HSTS を止める。**閉じたネットワークだけで使う** |

## DB 起動・接続

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `IDP_DB_AUTO_MIGRATE` | `true` | 起動時にスキーマを当てる。`false` なら未適用があれば起動を止める（`--migrate` で手で当てる） |
| `IDP_DB_MIGRATION_LOCK_TIMEOUT_SECONDS` | 300 | 複数インスタンスの同時起動で、マイグレーションの排他を待つ秒数 |
| `IDP_DB_SKIP_MIGRATION_CHECK` | `false` | `IDP_DB_AUTO_MIGRATE=false` のとき、未適用の検査を省く |
| `IDP_DB_ALLOW_INSECURE` | `false` | IdP 自身の DB への接続で、暗号化を切る・証明書を確かめない指定を許す。**検証環境だけ** |
| `IDP_PLEASANTER_DB_ALLOW_INSECURE` | `false` | 同、Pleasanter の DB 向け |

**既定は厳しい側。** SQL Server は `Encrypt=True` を常に立て、`TrustServerCertificate=True` や PostgreSQL の
`SslMode=Disable` などは、上の許可が無いと起動時に止める（`ConnectionSecurity`）。

## コマンドライン

| 引数 | 内容 |
| --- | --- |
| `--generate-secret-key` | `IDP_SECRET_KEY` に使える鍵を 1 つ出力して終了 |
| `--migrate` | 未適用のマイグレーションを当てて終了（`--wait-for-db=90` で DB の起動を最大 90 秒待つ） |
| `--migrate-status` | 未適用の一覧を出して終了（未適用があれば終了コード 1） |

## 登録（管理画面）

OIDC のクライアントと SAML の SP は、設定ファイルではなく **管理画面（または管理 API）で登録して DB に持つ**。
署名鍵も同じ（初回起動で自動生成。ローテーションは管理画面から）。
