# 機能一覧

状態の凡例: ✅ 実装済み・結合テストあり、🚫 対応しない（理由つき）。

## 認証

| 機能 | 状態 | 備考 |
| --- | --- | --- |
| Pleasanter のユーザーのパスワード認証 | ✅ | `Users.Password`（SHA-512）をそのまま照合。ログイン ID は大文字小文字を区別しない |
| TOTP（二段階認証） | ✅ | `Users.SecretKey` をそのまま使う。**認証アプリの再登録は要らない**。登録は Pleasanter で行う |
| TOTP を求める条件の切り替え | ✅ | `Auto`（登録済みの人）/ `Pleasanter`（Pleasanter の設定に従う） |
| 使用済みの TOTP の枠の再利用拒否 | ✅ | Pleasanter 本体には無い守り |
| 失敗の締め出し（パスワード・TOTP 合算、存在しない ID も同じ） | ✅ | IdP の DB に持つ。Pleasanter へは書かない |
| Pleasanter の無効・ロックアウト・ログイン期限・パスワード期限の尊重 | ✅ | 期限切れは Pleasanter での変更を案内 |
| SSO セッション（絶対期限・アイドル期限・失効） | ✅ | 管理画面から失効できる |
| メールによる二次認証 | 🚫 | 対応しない（Pleasanter の `NotificationType: Mail`） |
| パスワードの変更・TOTP の登録 | 🚫 | **Pleasanter の DB へ書けないため。** Pleasanter で行う |
| IP 制限・LDAP / 外部認証プロバイダ | 🚫 | Pleasanter の `ContractSettings` と認証プロバイダは引き継がない |

## OpenID Connect

| 機能 | 状態 | 備考 |
| --- | --- | --- |
| ディスカバリ・JWKS | ✅ | |
| Authorization Code + PKCE（S256） | ✅ | 公開クライアントは PKCE 必須 |
| ID トークン（RS256）・UserInfo | ✅ | `sub` は `UserId`。`amr` / `acr` で二段階認証を伝える |
| リフレッシュトークン（`offline_access`） | ✅ | ローテーションと再利用検知 |
| 認可コードの再利用検知 | ✅ | そのコードから出たトークンの系統を全て失効 |
| RP-Initiated Logout | ✅ | `id_token_hint` が無いときは確認画面 |
| トークンの失効（RFC 7009） | ✅ | リフレッシュトークンのみ（アクセストークンは自己完結の JWT） |
| クライアント認証 | ✅ | `client_secret_basic` / `client_secret_post` / `none`（公開） |
| スコープ・クレーム | ✅ | `openid` `profile` `email` `groups` `offline_access` |
| テナント単位の利用制限 | ✅ | クライアントごと |
| ユーザー・組織・グループの Include / Exclude | ✅ | OIDC クライアント・SAML プロバイダーごと。トークンを出すたび・SSO のたびに判定 |
| CORS（ブラウザ上の RP のため） | ✅ | ディスカバリ・JWKS は `*`。トークン・UserInfo・失効は、登録済みのリダイレクト URI のオリジンだけ |
| implicit / hybrid フロー、`request` オブジェクト、`form_post` | 🚫 | 対応しない |
| Back-Channel / Front-Channel Logout | 🚫 | 対応しない（RP 側でもセッションを閉じる） |
| 動的クライアント登録 | 🚫 | 管理画面で登録する |

## SAML 2.0

| 機能 | 状態 | 備考 |
| --- | --- | --- |
| IdP のメタデータ | ✅ | 旧鍵の証明書も含める |
| SP 起点の SSO（Redirect / POST の AuthnRequest → POST の応答） | ✅ | `ForceAuthn` / `IsPassive`（`NoPassive`）に対応 |
| 署名付き要求の検証・必須化 | ✅ | SP ごと |
| 応答・アサーションの署名 | ✅ | SP ごとに選ぶ（RSA-SHA256） |
| NameID（`emailAddress` / `persistent` / `unspecified` / `transient`） | ✅ | 元は `loginId` / `email` / `userId` / `globalId` |
| 属性の対応表 | ✅ | `groups` は複数値 |
| SP 起点の単一ログアウト | ✅ | cookie が無くても、署名付きなら閉じられる |
| SP のメタデータ XML の取り込み | ✅ | 下書きを作る（保存はしない）。DTD は禁止 |
| IdP 起点の SSO、Artifact、アサーションの暗号化、SLO の他 SP への伝播 | 🚫 | 対応しない |
